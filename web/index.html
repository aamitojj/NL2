Do these steps once. Not sure what a VPS is? Read the Guide first.

Step 1 — Your server (VPS)

Rent a Linux server (Ubuntu 24.04 LTS recommended) from Hetzner, DigitalOcean, etc. Your provider e-mails you its IP address and root password (or you add an SSH key).

Passwords are only kept in memory while HostPanel runs; they are never saved to disk.


  


  

    
Step 2 — Install Coolify on the server

    
Runs the official installer curl -fsSL https://cdn.coollabs.io/coolify/install.sh | bash on your server. Takes about 2–10 minutes. Skip if Coolify is already installed.

    Guide
    
  
    
    
    How it works
    
    
    Your websites live on your own rented server (VPS). On that server, Coolify (free, open source) runs each site in a small container and gets free HTTPS certificates. HostPanel is the remote control on your PC: it installs Coolify, uploads your site files, and connects domains. GitHub is not needed.
    
  
    
  
    
    
    1. Choose a server
    
    
      
      
    • Minimum for Coolify: 2 CPU cores, 2 GB RAM, 10 GB disk (from the Coolify docs).
      • 
      
    • For about 100 static sites: 4 vCPU, 8 GB RAM, 80+ GB SSD. Each site is one small nginx container (roughly 5–15 MB RAM each), plus Coolify itself (~1 GB). Example: Hetzner CPX31 / CX42 or a DigitalOcean 8 GB droplet.
      • 
      
    • Operating system: Ubuntu 24.04 LTS (or 22.04 LTS). Use a fresh server with nothing else on it.
      • 
      
    • Pick a data center close to your visitors.
      • 
      
    • Turn on the provider's automatic backups/snapshots.
      • 
    
    
  
    
  
    
    
    2. Firewall
    
    
    Allow incoming: 22 (SSH), 80 and 443 (websites), 8000 (Coolify dashboard; you can close it after you give Coolify its own HTTPS domain), and 6001, 6002 (Coolify real-time updates).
    
  
    
  
    
    
    3. Domains and DNS
    
    
      
      
    • Each customer buys a domain anywhere (Namecheap, GoDaddy, Cloudflare, TransIP, ...).
      • 
      
    • In the domain's DNS settings add an A record: Name @, Value = your server IP. For www add a second A record with Name www. HostPanel shows the exact records.
      • 
      
    • Delete old A/AAAA records for the same name that point somewhere else (for example the registrar's parking page).
      • 
      
    • On Cloudflare: set the records to DNS only (grey cloud) at least until HTTPS works.
      • 
      
    • DNS changes usually take minutes, sometimes a few hours. HostPanel checks automatically and connects the domain as soon as it points to your server. Coolify then requests a free Let's Encrypt certificate (HTTPS) within about a minute.
      • 
    
    
  
    
  
    
    
    4. Deploying a site
    
    
      
      
    1. Sites → Create site.
      2. 
      
    2. Choose a .zip or folder containing index.html and click Deploy. For React/Vue/Vite/Astro etc., build first (npm run build) and upload the output folder (dist or build).
      3. 
      
    3. Every deploy is kept as a release; you can switch back to one of the last 5.
      4. 
    
    
  
    
  
    
    
    5. Test before you deploy (App Testing)
    
    
      
      
    1. Open App Testing and load the same zip, folder or path you would deploy. HostPanel unpacks it into a temporary folder on your PC and starts a private preview server (only this PC can open it).
      2. 
      
    2. Click through the site in the built-in browser. Use the Phone / Tablet / Desktop buttons to see how it looks on other screens. JavaScript errors and files that fail to load appear in the Browser log under the preview.
      3. 
      
    3. Read the Check report: fail means visitors will see something broken, warn is worth fixing, pass is fine. Each item says what is wrong and how to fix it.
      4. 
      
    4. Fix problems in your files, then load again (or click Reload from disk & re-test when you used a path on this PC).
      5. 
      
    5. Choose the site and click Deploy this version. It uploads exactly the tested files.
      6. 
    
    
    
    Redirects and headers. HostPanel understands Netlify's _redirects, _headers and netlify.toml files. The preview applies them, and every deployment turns them into the live web-server config, so the preview and the live site behave the same. Examples for _redirects:
    

    # Single-page app (React, Vue, ...): every unknown address shows index.html
/*            /index.html     200
# Moved page
/old-page     /new-page       301
# Keep part of the address
/blog/:year/* /posts/:year/:splat  301

    
    
    Example _headers:
    

    /*
  X-Content-Type-Options: nosniff
/assets/*
  Cache-Control: public, max-age=31536000, immutable

    
    
    Good to know: an existing file always wins over a rule unless you add ! (e.g. 301!). Addresses are case-sensitive online even though Windows ignores case. /about serves about.html automatically. HostPanel never runs npm or build commands: build on your PC first and test the output folder (dist, build…). Netlify Functions and Netlify Forms are not available.
    
  
    
  
    
    
    Troubleshooting
    
    
    
      
    SSH connection failed
    Check the IP, that port 22 is open in the provider firewall, and the password. Some providers disable password login; use a key file instead (OpenSSH format; convert PuTTY .ppk with PuTTYgen → Conversions → Export OpenSSH key).
    
      
    "Host key changed"
    Normal if you reinstalled the server: click Forget host key. Otherwise do not continue.
    
      
    Coolify API error 401 / "Invalid token"
    Create a new token in Coolify (Keys & Tokens) and save it again. Make sure the API is enabled (Settings → Advanced).
    
      
    403 when creating a site
    The token needs the deploy permission (or root) because sites mount a folder from the server.
    
      
    Cannot reach Coolify
    Port 8000 is blocked: open it in the firewall, or tick "Send API calls through the SSH connection".
    
      
    Domain shows a certificate warning
    Wait 1–2 minutes after connecting. Check that both A records point to the server and there's no AAAA record pointing elsewhere. In Coolify, check that the proxy (Servers → localhost → Proxy) is running.
    
      
    404 / old content after deploy
    Make sure index.html is in the top folder of your zip. Hard-refresh the browser (Ctrl+F5).
    
      
    Redirect rules don't work on a site created with HostPanel 0.1
    The first deployment with 0.2 adds the rules folder to the container and restarts it once (about a minute). If the log shows a warning, use Redeploy container.
    
      
    "nginx rejected the generated config"
    One of your rules could not be converted. The live site was not changed. App Testing → Check report → Redirect and header rules shows which line to fix.
    
      
    Site status "exited" or "degraded"
    Click Redeploy container, then look at the deployment log in Coolify.
